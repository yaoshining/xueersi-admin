# 绿联 NAS 局域网部署

采用 Node 24、独立 Docker Compose 项目、HTTPS。默认使用单管理员密码认证，也支持用户明确选择的局域网免登录模式。**项目由用户在绿联 Docker → 项目创建和启动**，助手准备文件；后续可按用户授权直接重建该项目，不修改其他服务或公网路由。

## 部署包

先运行 `pnpm check`，再经用户明确授权后运行：

```sh
pnpm exec tsx scripts/prepare-nas.ts work/nas-package https://192.168.50.9:19473 192.168.50.0/24
```

上面的地址为合成示例，替换为实际 NAS 地址及家庭网段。脚本仅接受新的 `work/` 目录，读取已授权 `.env.local`、Mac 钥匙串和加密会话；在内存解密后用新随机密钥重新加密。不会打印真实凭据。真实运输模块单独打包在私有目录，不进入镜像。数据库使用在线备份，包含草稿和同步记录。

```
work/nas-package/
  project/
    docker-compose.yaml
    build/                 # 仅公开构建产物、锁定依赖、Dockerfile
    config/runtime.env     # 地址、路径、随机管理密码摘要
    private/transport.mjs  # 不公开的官方适配运输
    private/public-protocol.json # 运输模块必需的私有运行时配置
    private/sync-target.json # 同目录接口目标配置，同样不可公开
    data/drafts.sqlite
    data/vault/session.enc
    secrets/session.key    # NAS 独立密钥，32 字节
    secrets/server.key     # 服务 TLS 私钥
    secrets/server.crt
    secrets/ca.crt
  Xueersi-LAN-CA.crt        # 可以导入客户端的公开根证书
  管理登录.txt             # 仅自己的 Mac 保留，admin + 随机密码
  offline-ca/              # CA 私钥离线保留，不传 NAS
```

将 `project/` 内容通过已验证的 SSH/SFTP 传到 NAS 专用项目目录；父目录及目录 0700、文件 0600，所有者为容器 UID 1000。不使用公共共享目录。证书、密钥、密码不放入 Git、镜像层或绿联 Compose 编辑框。

## 绿联创建项目

1. Docker → 项目 → 创建，名称 `xueersi-admin`。
2. 选择专用项目目录，导入该目录中的 `docker-compose.yaml`。相对路径以这个目录为准，不另选临时目录。
3. 保留 Compose 中独立 LAN IPv4 端口绑定、非 root 用户、只读根文件系统、独立卷和自动重启策略。
4. 创建并构建。首次需要下载官方 Node 镜像和锁定的 npm 依赖，编译 SQLite 原生扩展；后续升级重新构建镜像。Dockerfile 不把秘密目录纳入构建上下文。
5. 查看容器是否 `running / healthy`。只绑定指定 LAN IP 的 19473 端口，不发布 HTTP、不修改端口转发或 Tunnel。

绿联必须支持 Compose `build`（标准 Compose 语法）。若该版本界面仅拉取现成镜像，先停止并反馈构建错误，再准备镜像导入包；不能删去认证或安全限制以绕过部署失败。

## 首次访问

默认 `NAS_AUTH_MODE=password`（省略时相同）使用下面的管理登录。若用户选择只信任家庭局域网，可在 `config/runtime.env` 设置 `NAS_AUTH_MODE=lan` 后重建容器；此模式不发出 Basic 登录弹窗，不需要填写账号密码，同一允许网段的设备均可查看和管理家庭作业。HTTPS、网段、Host、Origin、跨站请求检查与真实提交/删除的网页确认继续保留。不能把 LAN 模式用于公网、访客共享或转发入口。浏览器工具自身的地址访问策略与此设置独立，免登录不保证工具获得访问权限。

客户端需要信任 `Xueersi-LAN-CA.crt`。先核对证书 SHA-256 指纹；仅安装公开 CA 文件，不能安装 `server.key` 或 CA 私钥。Mac 可由本人在钥匙串中导入并信任；手机按系统提供的证书管理流程安装。**助手不跳过浏览器安全警告**。

打开配置的 HTTPS 地址，浏览器原生登录框输入账号 `admin` 和私有 `管理登录.txt` 中的随机密码。密码不通过聊天回显；是否保存到浏览器由用户决定。此版本没有独立账号/退出页面；需要撤销访问时轮换部署的管理密码，不依赖关闭标签页清除浏览器缓存的认证。仅局域网部署，不能转发到公网。

登录后 WebMCP 使用同一页面会话。查询、草稿和预览可在会话操作，真实提交/删除继续由用户在网页确认。服务不会自动布置、删除或完成作业。

从聊天或导航网站进入时，使用普通链接打开管理端页面即可。浏览器顶层 GET/HEAD 文档导航允许进入现有前端路由，包括总览、家庭设备、作业详情、草稿及同步预览；无需给导航网站开放 API 或配置 CORS。iframe 嵌入、跨站 API、资源读取及写入仍受来源限制。以后增加前端页面路由时，应同步更新 API 的文档导航范围与对应测试。

## 验收与切换

- 验证 TLS 证书和主机名，不使用 `curl -k`、`ignoreHTTPSErrors` 或浏览器忽略警告。
- 未登录页面/API 返回 401，错误 Host/跨站 Origin/非允许来源被拒绝。
- NAS 项目端口仅绑定指定 LAN IPv4，其他 Docker 服务未变化。
- 已认证只读连接正常，已有草稿和同步记录数量正确；不在终端打印家庭资料或令牌。
- 在绿联重启项目，确认健康、会话恢复与只读作业查询仍成功。
- Mac 和手机分别登录；核验 WebMCP、深浅主题与确认预览。测试期间不点真实提交或删除。
- 这些步骤完成后才停止 Mac 旧服务，保留只读回滚副本。切换验收期间暂停人工写入，避免源数据库在快照后变化。若需重新快照，先停止目标服务，再更新数据库和会话，避免双端续期竞争。

健康检查通过仅说明 HTTPS/服务存活，不等于官方会话或学习机已验证。Docker `restart: unless-stopped` 在进程退出时重启；`unhealthy` 状态本身不会自动重启。

## 凭据续期和再次交接

NAS 继续使用已迁移的 Cookie 自动续期；官方明确失效时提示登录，不保证永久免登录。此版 NAS 禁止浏览器跨站会话交接接口。

重新登录时：停止 NAS 项目，在 Mac 原流程完成本人验证码登录与扩展交接，然后生成新私有包。仅在停止目标服务的情况下成对替换 `data/vault/session.enc` 和 `secrets/session.key`；不要覆盖现有 NAS 草稿库。原 TLS 证书、管理密码配置和其他数据保留。通过已验证 SSH 传输，禁止把令牌复制到聊天或 Compose。这个流程由助手按授权协助执行。

## 备份、升级、回滚

- 初次创建前保留源数据库和会话；升级前在绿联停止项目，备份 `data/`、`config/`、`private/`，记录当前镜像标签。`secrets/` 单独放入受控备份，不能与公开资料一起分享。
- 使用应用 SQLite 在线备份 API或停止项目后复制完整数据目录，不能在运行时仅复制主数据库漏掉 WAL。
- 升级只替换 `build/` 并在绿联重新构建、重建；数据卷保持原样。镜像用新版本标签，保留旧标签。
- 失败时停止项目，恢复对应版本的数据库、密文、独立密钥和镜像；只启用一个实例。恢复 Mac 前需同步 NAS 上新增草稿，不能盲目使用旧快照。
- 容器日志仅保存少量轮转文件，不记录 Basic Authorization、Cookie 或官方原始响应。NAS 管理员能访问主机密钥，不承诺抵御 root。

## 验证边界

所有自动测试使用合成账号和数据。绿联创建、真实 NAS 镜像构建、客户端证书信任、官方只读恢复以及手机访问必须单独记录实际结果，不能由本机测试替代。
