## 实际运行修复与验收

首次真实构建已完成，但容器启动失败。启动日志为 `Cannot find module '/app/apps/api/dist/server.js'`；导出镜像元数据证实文件存在，但程序目录 0700、文件 0600 且所有者为 root，UID 1000 无法遍历读取。这是容器权限问题，本机测试未覆盖此构建边界。

Dockerfile 运行阶段 COPY 已补充 `--chown=1000:1000`，保留非 root 用户和私有文件权限。用户创建项目后新增授权直接使用 Docker 重建；已完成镜像重建，并在运行容器以 UID 1000 验证程序、页面、健康检查脚本可读且所有者正确。

第二处失败为运输模块运行时 JSON 资产未随模块迁移。使用合成模块分别复现导入和工厂初始化失败，新增受限资产清单打包，测试转为通过。实际私有资产只进入独立只读挂载，未写入公开源码或镜像；离线诊断证实模块可导入、会话能解密。

修复后 `pnpm check` 通过：42 个测试文件、138 项测试，12 项 OpenSpec 变更严格验证及全部工作区构建通过；公开索引扫描与本次修复文件扫描均通过。本次无页面行为变化，沿用前次 100 项通过、2 项跳过的端到端结果，不声称重新运行了这批浏览器测试。

实际 NAS 容器为 running/healthy，主动重启后仍健康、RestartCount 为 0。HTTPS 探测显式指定受信任 CA 并校验目标地址，未绕过 TLS；匿名页面返回 401、管理认证后返回 200。加密会话恢复后读取真实作业成功，状态从 pending 到 verified；孩子/设备显示名以及目标时长、提交要求字段可用。重启前后的只读结果与已保存草稿数量一致，详细业务数量仅留在私有验收输出。自动续期配置存在，本次未强制制造官方会话过期。

## 客户端协议报错定位与 WebMCP 实测

后续按用户要求仅排查客户端，没有改 NAS 配置。只读客户端代码和错误元数据证实：同一 NAS 侧栏在 HTTPS 导航后切换到内部 `data:` 错误页，对应错误码为 `ERR_INVALID_AUTH_CREDENTIALS`。本机隔离重放协议判断，HTTPS IP 与域名均通过，内部 data 协议不通过。失败的是认证错误页的协议检查，不能据此认定 HTTPS 或整个 NAS 地址被永久封锁。

## 外站导航误拦截修复

用户反馈从聊天或导航网站进入被 `ORIGIN_DENIED` 拒绝。原 guard 对所有 cross-site 请求直接拒绝，将正常的页面文档导航一并挡住。[Sec-Fetch-Site](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Sec-Fetch-Site) 和 [Sec-Fetch-Dest](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Sec-Fetch-Dest) 用于区分来源和目标类型。

在两种认证模式下，使用合成静态页面首先复现 403，再仅对 GET/HEAD、navigate/document 元数据和已知前端路由加入导航例外。全部现有入口（含家庭设备、作业详情、草稿编辑和批量同步预览）均有覆盖。API 即使携带文档导航元数据也不能使用例外；嵌入、资源、预检、写入、Host/网段伪造及密码模式缺少认证仍被拒绝。

最终 `pnpm check`：42 个测试文件、142 项测试通过；12 项 OpenSpec 变更严格验证与构建通过。端到端测试 100 项通过、2 项跳过。初次 lint 因新增测试的未使用变量失败，修复后通过，没有降低检查规则；补齐入口时的格式检查失败也在最终通过前修复。公开扫描和差异空白检查通过，实际截图留在忽略的 work。

已保留旧镜像并按用户后续 Docker 维护授权重建当前 app，容器 running/healthy、无异常重启。一次自动审批误按早先用户自行创建约定拒绝，补充用户后续明确授权及只读目标核验后，同一部署操作获准；未更换通道绕过审批。仅更新公开 API 构建产物，没有改 NAS 端口、认证模式、凭据或业务数据。

真实浏览器从临时不同站点的链接点击进入 NAS，页面完整加载、来源为测试页、“会话工具已就绪”可见。最终部署后的家庭设备与作业详情 HTML 请求为 200，伪装成文档导航的跨站健康 API 请求仍为 403。未提交、修改或删除真实作业，未创建测试草稿；用户自己的导航网站未直接操作，若采用 iframe 嵌入仍不在支持范围。
