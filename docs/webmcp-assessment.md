# WebMCP 接入评估

评估日期：2026-10-17。方案现已按 `enable-webmcp-task-tools` 实现，测试及当前浏览器实测见 [实施与验证](webmcp-verification.md)。

## 结论与实测边界

已作为现有 React 网站和本机 Node API 的渐进增强接入。当前 Codex 内置浏览器实际发现全部 10 个工具，完成查询、本机合成草稿创建修改与预览取消；最终真实写入仍留给家长本人在网页确认。

官方仍把 WebMCP 定义为提案；Chrome 提供 origin trial 和本地测试开关。网页需在支持的浏览器中打开，不能用它代替关闭浏览器后的后台任务服务。[官方概览](https://developer.chrome.com/docs/ai/webmcp)

当前官方命令式 API 使用 `document.modelContext.registerTool`，以 AbortSignal 管理注册生命周期。实现时应检测实际能力并封装版本差异，不直接依赖旧文章中的 navigator 接口；不支持时保留原有网页操作。[命令式 API](https://developer.chrome.com/docs/ai/webmcp/imperative-api)

## 与当前项目的结合

会话 → 浏览器 WebMCP → React 工具适配层 → 现有同源 `/api/v1` → 本机服务 → 官方接口。

- WebMCP 注册层放在 `apps/web/src/features/agent/`，与路由外壳同生命周期，避免只在月历页可用、路由切换后重复注册。
- 严格输入与返回结构放在 `packages/contracts`；复用当前草稿、作业、同步服务，不能另建绕过确认的写入通道。
- 使用现有 React Query 缓存刷新，工具创建草稿后页面立即显示同一结果。
- 本机后台继续保管加密 Cookie 和令牌。工具结果禁止包含会话令牌、Cookie、配对密钥、确认 secret、原始官方响应或带鉴权参数的附件 URL。
- 查询返回的必要作业文字会进入当前 AI 会话；“凭据只在本机”不等于“查询结果永不进入模型”。默认返回摘要与附件类型/数量，正文和附件按用户需要读取。
- 保留当前回环监听、Host/Origin 检查及本地请求头；不开放跨域 iframe 工具，不增加远程服务器。

## 建议工具范围

| 工具                            | 参数/返回要点                                            | 副作用与确认                             |
| ------------------------------- | -------------------------------------------------------- | ---------------------------------------- |
| `get_task_context`              | 连接状态、当前孩子和设备的显示名与本地引用               | 只读；不返回 sessionId 或真实官方标识    |
| `list_homework`                 | 明确日期区间、孩子引用；列表和完成状态                   | 只读，最多 42 天；分页/限制输出量        |
| `get_homework`                  | 作业引用；正文、目标时长、提交要求及报告摘要             | 只读；附件不直接暴露鉴权 URL             |
| `get_calendar_summary`          | 年月、孩子引用；每日总数/完成数/遗漏                     | 只读，复用统计模型                       |
| `list_drafts`                   | 本机草稿摘要                                             | 只读                                     |
| `create_draft` / `update_draft` | 日期、学科、正文、目标时长、提交要求；返回草稿引用与版本 | 仅本机保存；更新需版本校验，创建需去重键 |
| `preview_task_action`           | 同步草稿或删除未完成作业；返回目标、快照和预览引用       | 不调用官方写入；打开页面确认区           |
| `get_action_status`             | 预览/操作引用；等待确认、发送中、成功、失败或未知        | 只读；未知不可自动重试                   |
| `cancel_task_action`            | 预览引用                                                 | 取消本机待确认操作，不删除官方作业       |

第一阶段不暴露任意 fetch、脚本执行、任意 URL、文件路径、批量提交或批量删除工具。本轮不暴露草稿删除工具；不因其保存在本机就默认可以永久删除。

## 真实提交与删除的确认

现有服务已有五分钟预览票据、内容/会话/孩子/设备绑定、单次消费和重复操作阻止，可复用；但这只约束请求完整性，不能证明点击或 `confirmed: true` 来自本人。

推荐首版采用页面本人确认：

1. 会话创建预览，展示孩子、T6、日期、正文、时长、提交要求；删除还展示作业当前状态及不可恢复提示。
2. WebMCP 仅返回 `awaiting_confirmation` 和预览引用，不返回 ticket secret，也不注册最终提交/删除工具。
3. 由用户在现有确认页亲自确认，代理不得代点；会话工具随后查询结果。操作内容或目标变化、过期、取消后必须重新预览确认。
4. 后端仍重查任务状态、草稿版本及目标，复用单次票据、防重复和未知结果处理；测试中只用假运输。

这样会话可完成查询和准备工作，最终真实写入保留本人确认。它不是针对同源恶意脚本的隔离机制；页面代理和扩展的宿主权限仍是信任边界。

如果以后希望仅在会话中回复“确认”即可完成：须先验证宿主每次调用的可信确认/用户交互通道，并把其与具体预览绑定。工具不接受模型自行填写的确认布尔值作为授权证明。`consequentialHint` 只是提示，不能替代服务端确认机制；不支持可信确认时回退本人页面操作。[官方安全指导](https://developer.chrome.com/docs/ai/webmcp/secure-tools)

## OpenSpec 与 TDD 落地顺序（实施依据）

1. 新建 `enable-webmcp-task-tools`，先定义工具契约、结果脱敏、生命周期、查询范围和草稿幂等规则。
2. 合成数据试验：在当前内置浏览器注册一个只读工具，发现、调用、取消、路由切换后注销；记录宿主 API 差异，不改浏览器安全开关。
3. Red：未知字段/非法枚举/越权孩子/超范围拒绝；凭据不出工具返回；重复调用不生成多份草稿；旧版本更新拒绝；断连不混用演示数据；作业文字中的指令仅视为数据。
4. Green：查询、草稿与页面缓存同步；工具清单不含最终写入，预览不能直接提交/删除。
5. Red → Green：待确认、取消、过期、上下文变化、重复确认、官方失败和未知结果；HTTP 防护不因新增工具放宽。
6. `pnpm check`、`pnpm test:e2e`、脱敏检查；通过浏览器 WebMCP 真实发现/调用合成草稿。真实提交和删除的验收分别等待用户对具体操作确认。

## 后续独立会话接入

如果要求关闭网页后仍可操作，应单独评估本机 MCP 服务（例如 stdio）及 Codex 配置，它与 WebMCP 是不同接入方式。本轮不增加此服务或授权范围。
