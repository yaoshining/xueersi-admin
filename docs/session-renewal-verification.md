# 官方静默续期验证

2026-10-17 验证范围：现有本机加密保存的家长应用会话，仅官方认证与作业列表只读接口。

## 第一轮：仅使用已保存应用令牌

- 当前官方 Passport SDK 与此前分析版本内容一致。SDK 存储的认证令牌与家长 H5 通过 code/login 换取的应用令牌属于不同环节。
- 用现有应用令牌请求官方 SDK 的登录状态检查：HTTP 200、业务码 11100，响应要求删除 SDK 令牌。此响应没有写回本机凭据库。
- 用同一应用令牌请求 SDK 的应用令牌登录入口：HTTP 200、业务码 10006，未返回新令牌。
- 随后使用原本机应用会话重新读取作业成功。因此认证接口失败不能视为作业会话已经过期。

## 第一轮结论与限制

第一轮结果不能仅凭已保存的应用令牌实现经过验证的官方静默续期，也没有证明令牌自然过期后能恢复。没有启用生产自动刷新，不循环重试、不主动注销，也没有修改时钟制造过期。现有会话继续本机加密保存；官方拒绝该会话时仍需本人重新登录。

第二轮进一步观察官方客户端实际使用的认证凭据及交换流程。公开记录不包含账号、令牌、家庭、设备标识和私有协议常量。

## 第二轮：官方客户端实际观测

- USB 手机可访问，官方 App 正在运行；没有发现公开的 WebView 调试入口，近期 App 日志也没有续期标记。APK 的 Java 层有加固；作业 H5 通过原生 bridge 获取令牌，Flutter 含 `onTokenChanged` 通知。尚不能据此还原原生 Android 认证实现。
- 在 Chrome 官方邀请页面加载仅显示脱敏信息的观测器。页面没有应用 localStorage 令牌、SDK sessionStorage 令牌时，官方 SDK 自动请求登录状态接口，实际响应业务码 0，并在响应体中返回 `tal_token`；未观察到 `Set-Tal-Token` 响应头。SDK 源码使用 `withCredentials`。
- 返回的候选令牌在本机内存只读验证中与原保存令牌不同，并成功读取既有孩子的作业。候选令牌未写入凭据库，原会话没有替换。此结果证明候选令牌可用，尚未证明旧令牌过期后恢复。
- 将该候选令牌送入 SDK 的 tokenLogin 交换入口返回 11100；不继续重复此失败路径。
- 独立的不带 Cookie、不带令牌的请求返回 11100。该对照的设备标识与浏览器不同，不能单凭它把因果完全归于 Cookie。
- 用户已明确授权临时 Cookie 访问和本机内存对照。仅提取官方认证请求使用的 Cookie，交给一次性回环服务；没有持久化 Cookie。

## 第三轮：相同设备标识的 Cookie 对照

保持设备标识、官方认证接口及其他请求头一致，由本机 Node.js 发出请求：

| 对照          | 业务码 | 返回令牌                 | 作业只读验证 |
| ------------- | ------ | ------------------------ | ------------ |
| 不带 Cookie   | 11100  | 否                       | 不适用       |
| 带官方 Cookie | 0      | 是，与本机原保存令牌不同 | 成功         |

带 Cookie 的响应还包含 Set-Cookie。此结果支持：在本次账号状态下，官方认证 Cookie 可在没有应用令牌的情况下取得可用作业令牌。它不证明 Cookie 永久有效，也不证明 Android 原生客户端使用相同机制。

## 第四轮：关闭官网页面后的延时验证

1. 将官方 Cookie 一次性交给本机进程内存，首次取得令牌并成功读取作业。响应的 `expire` 为 48；本轮首次响应的 Cookie 值未改变。
2. 关闭官方页面，并恢复验证器原配置、重新加载扩展，撤销临时 Cookie 权限及认证域名权限。
3. 本机等待 56 秒后，旧候选令牌仍能读取作业。
4. 本机独立使用内存中的 Cookie 再次请求官方认证接口，取得与前一次不同的新令牌；响应同时更新了 Cookie 值，`expire` 为 300。新令牌读取作业成功。

因此，已经验证无验证码、无需保持官网页面打开的令牌换取，以及服务端 Cookie 更新。**尚未验证作业接口实际拒绝旧令牌后的自动恢复**；`expire` 不能直接解释为作业令牌失效时间。`life` 的长期数值也不能作为稳定登录时长承诺。

## 收尾与实现边界

- 本次候选令牌和 Cookie 仅在一次性进程内存使用；进程已退出，回环端口已关闭。
- 原本机加密会话未替换，未新增凭据落盘。验证器已恢复原版本与权限，临时观测脚本已移除。
- 没有改手机系统、代理或证书，没有真实作业写入。
- 私有探针的合成数据测试通过：固定官方目的地、拒绝 Cookie 请求头注入、脱敏输出、仅观测允许的认证请求。
- `pnpm check` 通过：54 项单元测试、5 项 OpenSpec 校验、格式、Lint、类型检查和构建；`pnpm check:public` 通过，新增记录另经人工脱敏审阅。构建保留已有 Shader 懒加载包体积提示。本轮未改页面，无新增 E2E 运行。
- 尚未启用产品中的自动续期。后续可按 OpenSpec 与 TDD 接入：本机加密保存经授权的认证 Cookie、处理响应 Cookie 更新、串行续期并重试一次只读请求、认证失效时回退本人登录。该接入需要将本次“仅内存临时验证”明确扩展为本机长期保存授权。
- 官方原生 Android 客户端的完整更新链路仍未验证；本轮证据来自官方 Web SDK 和对应认证服务。

## 后续接入：本机 Cookie 自动续期

前述“尚未启用”描述对应研究阶段。用户随后明确授权 Cookie 本机加密保存，`enable-cookie-session-renewal` 已按 OpenSpec 和 TDD 实现并完成只读接入。

- Cookie 和令牌使用原 AES-256-GCM 保险箱及钥匙串密钥原子保存；通过扩展专属一次性配对交接，读取验证成功才提交。
- 五分钟按需检查，无空闲轮询；认证失败合并续期，最多重试一次只读请求。网络失败保留凭据并退避，明确认证拒绝后提示重新登录。
- 官网关闭且临时权限撤销后，服务重启成功恢复；等待检查时间后，正常只读请求实际触发令牌和 Cookie 更新，保存后作业读取成功。
- 69 项单元/集成测试、52 项 E2E 通过（2 项按平台跳过），6 项 OpenSpec 校验通过。真实自然失效仍未观察，不承诺永久免登录。
