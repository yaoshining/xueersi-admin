# Design

## Context

现有 SyncService 以短期内存票据绑定草稿快照、会话和设备，通过 SQLite fingerprint 占位避免重复写入。sync_jobs 保存完整草稿摘要，但 store.list 未过滤成功记录。真实确认必须由用户在网页完成。

## Goals / Non-Goals

Goals：兼容历史记录、批次全部预检、一次确认、逐条结果、桌面及移动深浅主题。
Non-Goals：官方批量接口、自动确认、自动重试、自动删除已同步作业、扩展 WebMCP 最终写入能力。

## Decisions

1. 使用现有 accepted 记录与规范化草稿快照匹配，从待同步列表排除；修改后的草稿是新版本，保持待同步。已同步列表直接展示不可变记录，原草稿删除也不影响历史。无需新增状态列和历史迁移。
2. 当前孩子范围内多选；未知/发送中记录对应草稿保留但标为待核对且禁止同步。记录读取失败时禁用批量选择；不得猜测状态。保留旧单条入口。
3. 批次 1–20 条，拒绝重复 ID 及内容指纹。预览不写官方；所有条目校验成功才签发一张批次票据。票据仅绑定服务端选择快照，不接受确认时追加草稿。
4. 确认前预检全批快照、会话、设备、期限、类型及防重；消费票据后顺序提交，复用单条发送的持久占位。提交每条前再次校验，出现 failed/unknown/预检失败立即停止，余下标记 not_sent。没有事务回滚，也不声称批量原子性。
5. 逐条写入已有同步记录；网页丢失或服务重启可从历史核对，sending 解释为 unknown 并防重。批次票据不持久化；重新运行只可针对失败/未发送项重新预览确认。
6. 使用现有 Button、Card、ToggleGroup 等 shadcn 组件，选择控件 aria-pressed、触摸尺寸、布局自动换行。预览完整展示每项内容及提交选项。

## Risks / Trade-offs

- 官方接受不等于学习机接收 → 显示证据边界。
- 网络断开时服务器可能继续执行 → 不自动重发，显示同步记录入口，逐条记录可回读。
- 外部操作无法回滚 → 明确部分完成和停止后续。
- 多页并发确认 → 复用原子 fingerprint 占位和一次票据。

## Migration Plan

构建测试后重启本机服务；历史记录直接生效，不修改私人作业数据。回滚代码不损坏已有 drafts/sync_jobs。
