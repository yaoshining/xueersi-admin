# Design

## Context

服务固定回环地址，尚无登录；保险箱为 AES-256-GCM，密钥由 macOS 钥匙串提供。NAS 经只读核实为 Linux x86_64，Docker/Compose 可用，支持绿联项目。主规格目录为空，既有行为由活动变更描述。

## Goals / Non-Goals

目标为无人值守启动和家庭局域网访问。默认采用浏览器原生 HTTP Basic 登录（仅 HTTPS）；用户明确选择免登录时可配置 LAN 模式，不新增账号管理 UI，不开放公网。不会自动点击官方提交/删除。

## Decisions

- 外站点击进入属于浏览器顶层文档导航，与跨站 API 调用区别处理。仅在 GET/HEAD、`Sec-Fetch-Mode: navigate`、`Sec-Fetch-Dest: document` 且路径属于已知前端页面路由时，允许跨站来源进入页面。网段、Host 和密码模式认证仍先检查；API 即使伪装导航也不能走此例外，iframe、资源读取、预检和写入继续拒绝。页面加载后的同源请求保持原有行为，无需对导航网站建立信任名单或开放 CORS。

- `NAS_AUTH_MODE` 仅接受 `password` 或 `lan`，未配置时保持密码模式。只有显式 `lan` 才跳过 Basic 检查和认证挑战头；同网段设备因此可以查看与管理家庭作业，用户已选择此边界。两种模式都必须保留 TLS、精确 Host、真实来源网段、Origin / Sec-Fetch-Site 和写入自定义头校验。未知模式和残缺 NAS 配置拒绝启动。

- 采用应用原生 TLS 与认证：少一个反向代理依赖，不修改已有 NAS nginx。NAS_ORIGIN 必须为 HTTPS 私有 IPv4 地址且来源网段明确；绑定容器端口到 NAS 的 LAN IP，不开启 IPv6/路由端口映射。应用不信任转发头。
- Basic 管理密码为生成的 256 位随机值，服务仅存 SHA-256 摘要并恒时比对；密码放私有交付文件，禁止 URL/日志携带。浏览器负责登录框，不自建弱口令账号系统。失败限速，全站认证，精确 Origin 与写入自定义头继续执行。仅无敏感信息的健康检查允许容器回环访问。
- Linux 密钥是独立只读挂载的 32 字节文件，校验普通文件、所有者、权限；不进镜像、Compose 或环境变量。会话使用原保险箱格式重新加密，NAS 与 Mac 密钥不同。
- TLS 使用专用私有 CA 签发的 LAN IP 证书，根私钥离线保留在 Mac 私有目录，不传 NAS；仅服务私钥传 NAS。首次需用户信任公开 CA 证书，绝不跳过浏览器证书警告。
- 镜像仅包含构建产物与运行依赖。真实运输模块和保险箱以私有卷挂载，Compose 由绿联 Docker 项目导入并管理；SSH 只准备文件、构建镜像及验收。
- 迁移脚本在内存读取 Mac 会话，重新加密后写入私有临时目录，经 SSH 传输。SQLite 使用在线备份 API。服务迁移验收期间冻结人工写入，切换后保留只读旧副本作回滚，避免双端续期竞争。
- 既有扩展仍连接 Mac；NAS 不接受跨站 pairing/renewal。官方失效后本人在 Mac 登录，再通过同一受控 SSH 流程重新封装会话；不扩大扩展网络权限。

## Risks / Trade-offs

- 私有 CA 首次信任需要用户操作；在受信任浏览器与手机的验收前不宣称全设备完成。
- Basic 认证没有完善的退出界面；需轮换随机密码撤销访问，不能依赖浏览器关闭标签页清除认证。LAN 模式信任允许网段内的设备，不提供用户身份隔离。两种模式都不可通过 HTTP 使用。
- NAS 管理员可同时访问密钥与密文；加密用于隔离普通用户/备份误泄露，不承诺抵御 NAS root。
- 普通 Compose secret 本质是文件挂载；NAS 权限和独立备份仍须执行。
- 官方 Cookie 可能自然失效；保持失败提示与本人重新登录流程。

## Migration Plan

先完成合成 Red/Green 测试及全部质量门槛，生成私有部署包、证书和随机管理密码，由用户使用绿联项目创建，助手仅准备并交付文件。仅做健康、身份认证、作业读取和重启恢复验收；不真实写入。验收后停止旧 Mac 服务。失败时停止 NAS 项目、恢复旧服务与冻结前备份，不能同时启用两个会话写入者。
